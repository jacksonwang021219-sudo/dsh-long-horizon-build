# 改造已有 topic

目标是在保持现有内容可用的前提下，让后续 Agent 容易理解、复用和接续。

## 流程

1. 读取现有 README、目录、代码入口、数据位置和路径依赖。
2. 识别已有任务、跨任务知识、运行产物和历史材料。
3. 补充 topic README，使其能回答：
   - 这个 topic 是什么；
   - 目录内容放在哪里；
   - 新任务如何开工；
   - 已有任务及交付在哪里。
4. 按实际任务类型补充类型 README 和 `_TEMPLATE/`。
5. 将稳定的数据知识和方法分别整理到 `shared/DATA.md`、`shared/METHOD.md`。
6. 单次任务的定义、进展、结论和接续位置保留在该任务 README。

## 约束

- 以增加导航和文档为主，不为套模板强制重排目录。
- 保留仍有用途的历史文件、脚本和产物。
- 只有确有必要时才移动文件；移动前检查路径引用和运行影响。
- 若目录尚非 git 仓库，先配置 `.gitignore`、检查大文件，再执行 `git init`。
- 若目录已经是 git 仓库，先检查 `.gitignore` 和已被跟踪的大文件。
- 已进入 git 历史的大文件只报告，不自动清理或改写历史。

`doubaowork/` 与 `VC/` 的现有组织方式可作为主要参照。
